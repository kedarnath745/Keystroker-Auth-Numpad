## 1. Executive summary

This project implements a Keystroke Dynamics Authentication System using a React frontend and a FastAPI Python backend with per-user machine learning models. It captures raw keystroke events, extracts timing features, trains per-user classification models (ensemble of SVM / RF / KNN / Gradient Boosting), and performs real-time authentication and device-type classification (numeric keypad vs top-row digits).

## 3. End-to-end data flow

1. Frontend captures raw key events: events contain key, key_code, timestamp, event_type ('keydown'/'keyup') and typed text.
2. Frontend posts events to backend enrollment/authentication endpoints (payload matches Pydantic KeystrokeDataInput).
3. Backend runs feature extraction (hold times, down-down intervals, up-down intervals, typing speed, rhythm variance, etc.) to produce a numeric feature vector.
4. For enrollment:
   - The backend accumulates multiple patterns per user and calls KeystrokeMLPipeline.train_user_model(user_id, feature_vectors, labels).
   - Trained models and scaler saved to disk (joblib) under backend models directory.
5. For authentication:
   - Backend loads user model bundle, scales incoming vector, obtains per-model predicted probabilities, composes ensemble score, compares with threshold → returns AuthenticationResponse with confidence, status, processing time and device-type if classified.
6. System stats endpoint aggregates counts, recent activity and simple metrics for SystemStats.js to display.

## 4. Feature engineering (expected)

Feature extraction file is referenced but not attached. Based on models.py and README, features include:
- Key-level timing:
  - Hold times: duration between keydown and keyup for each key.
  - Down-Down (DD): interval between consecutive keydown events.
  - Up-Down (UD): time from keyup to next keydown.
- Aggregated / statistical features:
  - Total typing time.
  - Typing speed (characters per second or WPM).
  - Rhythm variance (statistical variance of intervals).
- Optional derived features:
  - n-gram timing features, mean/median/std for hold/DD/UD vectors.
  - Per-key timing normalization if needed.
Important: ML pipeline assumes a consistent ordering of feature_vector across training and scoring. Confirm feature_extraction.py to ensure ordering and scaling compatibility.

## 5. ML pipeline details (backend/ml_pipeline.py)

- Models initialized:
  - SVM (RBF, probability=True)
  - RandomForestClassifier (n_estimators=100, max_depth=10, min_samples_split=5, min_samples_leaf=2)
  - KNeighborsClassifier (n_neighbors=3 by default, weights='distance')
  - GradientBoostingClassifier (n_estimators=100, max_depth=6)
- Preprocessing:
  - StandardScaler for feature normalization.
  - LabelEncoder for categorical device/type labels.
  - SMOTE used to oversample minority class when dataset size permits (k_neighbors adapted to avoid errors on small datasets).
- Training strategy:
  - Per-user training: positive class = user samples, negative class = imposter samples (explicit negatives or synthesized).
  - Minimum sample checks: pipeline raises if fewer than 5 samples for a user.
  - If no negative samples exist, synthetic imposters are generated by adding Gaussian noise to positive examples (noise_level e.g., 0.3).
  - Cross-validation: StratifiedKFold with fold count adjusted to sample counts.
  - An ensemble VotingClassifier (soft voting) is built from the successfully trained models.
- Threshold selection:
  - _calculate_optimal_threshold sweeps candidate thresholds to approximate equal-error-rate (minimize difference between FAR and FRR) and stores a per-user threshold; default fallback = 0.6.
- Persistence:
  - Models and scaler saved per-user via joblib into backend models directory (e.g., ./models/{user_id}_models.joblib).
  - Device-type classifier saved into a consolidated device_type_models.joblib.
- Device-type classification:
  - Trains a global classifier (same model families) to predict InputDeviceType enum (keyrow vs numpad).
  - Uses its own scaler and label encoder; serves probabilities and predicted label.

## 6. Authentication flow (runtime inference)

- Load model bundle for user (if cached or on disk).
- Scale incoming feature vector with saved StandardScaler fitted for that user.
- For each model:
  - Use predict_proba (if binary classification) to get probability that the sample belongs to the user.
  - If a model cannot produce a probability (single-class or failure), pipeline handles gracefully and may skip that model.
- Ensemble:
  - If ensemble exists, use its probability; otherwise average model probabilities.
- Decide:
  - Compare final confidence to stored per-user threshold (or default threshold). If confidence >= threshold → success.
- Return metadata: processing_time_ms, model_predictions map, ensemble_score, threshold_used, predicted_device_type.

## 7. Small-data & robustness strategies

- Synthetic imposters generation when only positive samples exist.
- Adaptive SMOTE usage — disabled when dataset too small to avoid k-neighbors errors.
- Adaptive KNN n_neighbors fallback to <= number of samples.
- Adaptive CV fold count to prevent invalid folds.
- Exception handling around training/prediction so partial model failures do not crash the pipeline.
- Random seeds (random_state=42) set for reproducibility.

## 9. Deployment & runtime notes

- Backend: FastAPI + uvicorn. Example:
  - uvicorn server:app --host 0.0.0.0 --port 8000 --reload
- Database: README references MongoDB for persistence (users, pattern metadata, authentication_attempt logs). Confirm `server.py` for actual database usage and connection URIs.
- Models: saved on filesystem with joblib. For multi-instance deployments, store models in shared object store (S3 / network share) or use central model service.
- Performance: The system claims sub-100 ms processing. To achieve that in production:
  - Keep models in memory or a warmed model cache.
  - Use vectorized numpy operations and optimized I/O.
  - Limit heavy operations (SMOTE / retraining) to background tasks.

## 11. Security & privacy considerations

- Keystroke data is sensitive behavioral biometric data:
  - Encrypt keystroke data at rest (DB encryption) and in transit (HTTPS).
  - Secure model storage and access control (who can download per-user models).
  - Anonymize or redact logs when possible.
- Rate-limit authentication attempts to prevent brute-force and replay attacks.
- Add replay detection: compare event timestamps/deltas for reasonable ranges and limit repeated identical patterns.

## 12. Recommendations & improvements

- Versioned model store (include model metadata: training_date, sample_count, cv_scores).
- Model explainability: store feature importances for RF/GB to identify distinguishing features.
- Better negative sampling: collect shared public impostor pool rather than only synthetic noise for more realistic negatives.
- Per-device normalization: train device-specific scalers or include device-type as a model input to reduce variance between numpad and keyrow.
- Continuous learning: incremental updates of user model using streaming patterns with secure re-training pipeline.
- Dockerize backend and reference docker-compose for reproducible deployment.
